## What each mode does (`src/longvid_ov/tiled_decode.py`)
The decoder IR is called once per tile; tiles overlap and the overlap is cross-faded with a linear ramp (`previous * (1 - k/n) + new * k/n`, weights sum to 1). Tile sizes, strides, overlap, blend formula and blend order are those of diffusers 0.39 `AutoencoderKLLTXVideo` (`tiled_decode`, `_temporal_tiled_decode`, `blend_v/h/t`).

| mode | what is decoded per call | memory bounded in | diffusers equivalent |
|---|---|---|---|
| `none` | the whole latent tensor | nothing | default |
| `spatial` | one H/W tile of all frames | height, width | `enable_tiling()` |
| `temporal` | one chunk of latent frames (chunk/8 + 1), full H/W | frames | `use_framewise_decoding = True` |
| `spatial+temporal` | one H/W tile of one chunk | frames, height, width | both |

Like diffusers, a mode falls back to a plain decode when the input is not larger than one tile / one chunk. Unlike diffusers, tiles are blended and written to the output as they are decoded (only the previous chunk / previous row of tiles is kept), and a trailing chunk that would contribute no frames is not decoded.

**First-frame rule.** The decoder turns the first latent frame of whatever it is given into ONE video frame and every other latent frame into 8. A chunk starting at latent frame i > 0 therefore begins with an extra frame (video frame 8i) that the previous chunk already produced. `drop_first` (ours) drops that frame, so the chunk starts at frame 8i+1, where it is pasted. diffusers 0.39 drops the chunk's LAST frame instead, so the chunk starts at frame 8i but is still pasted at 8i+1 (`first_frame_rule="diffusers"` reproduces that for the port check).

## What broke and how it was fixed

1. **diffusers' temporal tiling shows every frame after the first chunk one frame late.** `_temporal_tiled_decode` trims each chunk with `decoded[:, :, :-1]`, but the surplus frame is the chunk's FIRST one (the causal frame); its encode twin `_temporal_tiled_encode` does drop the first (`tile[:, :, 1:]`). Found by decoding with a toy decoder that just repeats each latent frame (tiled must then equal untiled exactly; it did not), confirmed on the real VAE in the first-frame-rule table above. Fix: `first_frame_rule="drop_first"` (the default); the diffusers rule is kept only so the port can be proven identical to diffusers.
   - `ov_512x320`, 49 frames, spatial+temporal: PSNR vs untiled 29.31 dB with the diffusers rule, 40.01 dB with ours.
2. **diffusers decodes all tiles first and blends afterwards**, so it holds every decoded tile at once. The port blends each tile as soon as it is decoded and keeps only what the blend reads (previous chunk, previous row of tiles); the port-check table shows the output is unchanged.
3. **diffusers runs the decoder on a last chunk of one latent frame and discards the result** (it decodes to the single causal frame, which is then trimmed). The port skips that call.
4. **The infer request reuses its output buffer.** The blend writes into the decoded tile in place, and the previous tile is read again when the next one is blended, so `OVDecoder` returns a copy of the output tensor.
